# ROMKit — 模拟器游戏库整理工具

一个类似 OfflineList 的本地 ROM 清单整理工具，**完全兼容 OfflineList 的 DAT 格式**，并在此基础上补上它最缺的能力：**每个 DAT（清单）可以独立选择"保留压缩包 zip"还是"保留原始文件"**。

## 快速开始

1. 双击 `start.bat`，会弹出一个命令行窗口并自动打开浏览器（`http://127.0.0.1:8765`）
   - **这个窗口就是程序本体，用的时候别关**；关掉窗口 = 退出程序
   - 需要 Node.js 18+，脚本会自动在 PATH、`Program Files\nodejs`、`LocalAppData\nvm` 等常见位置查找
2. 把 OfflineList 的 DAT（如 `CHS_GG_OL.zip`、`CHS_PS2_OL.zip`）**直接拖进窗口**，或点「从本地路径添加」
3. 点击右上角 ⚙ 打开清单设置，填入 **ROM 源目录** 和 **整理输出目录**，选择输出形态
4. 点「扫描」→ 确认匹配结果 → 点「整理」→ 预览计划 → 开始整理

> 不用了想彻底关闭：关掉那个黑色命令行窗口即可（或在窗口里按 Ctrl+C）。

### 启动失败排查

| 现象 | 原因与处理 |
|------|-----------|
| 双击后窗口一闪而过 | 先看 `data\start.log`（脚本每次启动都会记录 Node 路径与退出码） |
| 提示「不是内部或外部命令」 | 旧版 `start.bat` 的编码问题，当前版本已修复（纯 ASCII + CRLF） |
| 提示 Node.js not found | 去 nodejs.org 装 LTS 版即可；脚本已自动搜索 PATH、Program Files、nvm、scoop、winget 等常见位置 |
| 浏览器打开是白屏 | 端口可能被占用，程序会自动换端口，请以窗口里打印的地址为准 |
| 提示端口被占用后仍失败 | 关闭其他占用 8765 端口的程序，或设置环境变量 `ROMKIT_PORT=9000` 再启动 |

> `start.bat` 由 `tools/gen-startbat.js` 生成（保证 CRLF + 纯 ASCII，避免 CMD 解析错乱）。
> 如需修改启动逻辑，请改生成器再执行 `node tools/gen-startbat.js`，不要直接手改 .bat。

## 核心功能

### 兼容 OfflineList DAT
- 支持 `.xml` 和 `.zip`（内含 xml）两种形式，中文标题、注释、标签、CRC 全部解析
- 保留 DAT 内置的在线更新源（`datVersionURL` / `datURL`），点「更新 DAT」即可检查并下载新版本，与原版 OfflineList 更新源完全一致
- 匹配规则与 OfflineList 一致：按解压后内容的 **CRC32** 精确比对（zip 直接读目录里的 CRC，无需解压，秒级扫描）

### 每个 DAT 独立选择输出形态（原版没有的功能）
| 形态 | 行为 |
|------|------|
| 保留压缩包 | 每个游戏输出一个 `.zip`（单条目，内含原始 ROM，zip 内文件名与外层一致）|
| 保留原始文件 | 不打包直出 ROM 本体；源是 zip 时自动解压（如 `.chd`、`.gg`）|

编号说明：`%u` 用清单里的**序号**（与列表显示一致）。DAT 的 `imageNumber` 会被多条记录共用（例如 BIOS 与主文件同号），不适合做文件名。

配套选项：**命名模板**（见下）、复制/移动、冲突处理（跳过/覆盖/改名）、递归子目录。

两个贴心行为：

- **目标位置已经有这个游戏的文件时，一律标记「已就位」**，不会生成 `xxx (1).zip`，也不会误删源文件（尤其是「移动」模式 + 输出目录＝源目录的组合）
- **整理结束后立即按执行结果更新状态**（不重新读盘）。统计、文件位置马上就是准的；扫描结果也会写入 `data/cache/`，下次打开不用重扫。

整理时还会把 CRC 缓存一起搬到新路径：文件被复制/移动/改名后，下次扫描直接命中缓存，**不会再把几百 MB 的文件重读一遍**（重新打包 zip 的情况除外，那种内容确实变了）。

### 多盘游戏

Disc 1 / Disc 2 这类多盘游戏，勾选「多盘游戏放进同一个文件夹」后：

```
莎木2 (Disc 1).chd          →   0012 - 莎木2 (公测版) (简) [yzb]/
莎木2 (Disc 2).chd                   ├─ ... (Disc 1).chd
莎木2 (Disc 3).chd                   ├─ ... (Disc 2).chd
莎木2 (Disc 4).chd                   ├─ ... (Disc 3).chd
                                     └─ ... (Disc 4).chd
```

- **识别规则**：DAT 里多盘通常是**多条独立记录**（`0012 莎木2 (Disc 1)`、`0013 莎木2 (Disc 2)`…），但共用同一个 `imageNumber`；程序按「相同编号 + 去掉 disc 后的标题」归组，所以即使它们编号位置不同也能认出来
- 文件夹名用命名模板生成并**去掉 disc 标记**；每个盘的文件名仍用它自己的模板渲染（编号与列表一致）
- 文件名保留各自的盘号，不会互相覆盖
- 多盘之间**不会被当成「重复副本」移走**
- 只输出实际存在的盘；缺盘不影响其他盘归组
- 目标子文件夹会自动创建
- 仅「保留原始文件」模式生效（压缩包模式每个盘是独立 zip）

### 纹理包

勾选「纹理包与主文件放进同一个文件夹」后，标题里带「(纹理包)」的条目会与同名主文件归到一起：

```
GT赛车4.chd                    →   0010 - GT赛车4 (简) [yzb]/
GT赛车4 (纹理包).chd                   ├─ 0010 - GT赛车4 (简) [yzb].chd
                                        └─ ... (纹理包).chd
```

- 识别词：`纹理包`、`材质包`、`高清纹理`、`texture pack`（中英文括号都支持）
- 文件夹名用**不带**「(纹理包)」的那个条目的命名
- 仅「保留原始文件」模式生效

### 移动后清理空文件夹
用「移动」方式整理后，会**扫描整个 ROM 目录**，把空文件夹删掉（只删空的，不删根目录，跳过系统目录）。不只处理"本次搬空的"，以前整理留下的历史空目录也会一并清掉。可在设置里关闭。

### 命名方式（与 OfflineList 完全一致）

默认模板 `%u - %n [%g]`，可分别设置：

| 模板 | 作用 |
|------|------|
| 文件名模板 | 输出裸文件时的文件名；压缩包内条目的名字 |
| 压缩包名模板 | zip 模式下压缩包的文件名（可与文件名不同）|

占位符（点击设置面板里的标签可直接插入）：

| | | | |
|---|---|---|---|
| `%n` 游戏名称 | `%p` 发行厂商 | `%i` 容量大小 | `%u` 游戏编号（补 3 位）|
| `%c` CRC | `%o` 发行国家 | `%g` 发布来源 | `%s` 存档类型 |
| `%e` 备注 | `%a` 语言 | | |

> `%o`/`%a` 优先从 DAT 的 `comment` 标签里取（如 `(Japan)` `[CHS]`），取不到才回退成 DAT 里的数字代码。
> 另外兼容旧写法 `{title}` `{crc}` `{publisher}` 等。

**压缩包内文件是否同步改名**：勾选时 zip 内部条目按「文件名模板」命名（与压缩包同名），取消则保留 ROM 的原始文件名。

> 游戏编号 `%u` 统一补足 **4 位**（`0001`），与 OfflineList 的列表显示一致；界面左侧的编号按钮也是同一个值。

### 未识别 / 多余的文件

扫描时除了匹配清单，还会记录**没匹配上任何条目**的文件（含读不出内容的 7z/rar）。设置里可选：

- **留在原处**（默认）—— 不动
- **整理时移动到指定目录** —— 整理时把这些文件挪到你指定的「未识别」目录，保持 ROM 目录干净

只移动候选池里的文件（扩展名符合 DAT 的 ROM 或压缩包），`.txt` `.jpg` 这类杂项不会被动。若目标目录设在 ROM 目录内部，预览会给出警告（避免下次扫描又扫回来）。

### 多份副本只留一份

同一个游戏在目录里有多份时（比如既有一份原始下载的文件、又有一份已经整理好的），可以选：

- **全部保留**
- **只保留文件名正确的那一份，其余移走**（默认）
- **只保留文件名正确的那一份，其余直接删除**（整理前会二次确认）

「文件名正确」按命名模板判断，打分顺序是：外层文件名与模板一致 > 压缩包内条目名与模板一致 > CRC 匹配 > 裸文件 > 单条目压缩包。移走模式的目标目录默认为「未识别」目录，都没设置则放 `data/duplicates/<清单>`。

安全规则：**压缩包里还装着别的游戏时不会被移动**（会提示有多少个这样的情况），避免误伤合集包。

### 游戏详情

点击列表任意一行，右侧滑出详情面板：

- 顶部是**大图**，下面一排小图可切换（**封面** / **截图**），鼠标移到图上会出现左右箭头，也可直接点小图
  - 封面对应 DAT 的 `im1CRC` 和 `{编号}a.png`
  - 截图对应 `im2CRC` 和 `{编号}b.png`
- 下方是编号、标题、英文名、发行国家、发行厂商、发布来源、容量、存档类型、语言、CRC、状态
- 最下面是文件位置，多份副本会分别列出，并标注是「CRC 校验」还是「文件名匹配」

### 游戏截图 / 封面

列表首列直接显示缩略图，点击可放大查看、上传替换或移除。

三种来源，自动按优先级取用：

1. **工具存储目录** —— 手动上传或从订阅源下载得到的图（默认 `data/covers/<清单>`，**可在设置里改成自己的图片目录**）
2. **已有截图目录** —— 指向现成的图片包，只读不改。会**递归扫子目录**，支持这些命名：
   - `{im1CRC}.png`（OfflineList 标准，如 `FDB775AB.png`）
   - `{编号}a.png`（封面）/ `{编号}b.png`（截图）（Romulus 图片包，如 `1-500/2a.png`）
   - `{编号}.png`、`{标题}.png`
3. **订阅源** —— DAT 里的 `imURL` + `im1CRC`，点「下载缺失」批量下载（需要联网）

   实测可用的地址规则（emugif，2026-10）：
   ```
   https://dat.emugif.com/img/gg/{编号区间}/{编号}a.png?crc={im1CRC}
   例：https://dat.emugif.com/img/gg/1-500/2a.png?crc=1B291097
   ```
   编号区间按 500 个一组（`1-500`、`501-1000`…）。程序会依次尝试这条主规则和若干备用命名（无 crc 参数、旧式扁平 `{im1CRC}.png` 等），命中即停。

   设置里有「地址测试」按钮，可对第一个游戏逐个打候选地址，直接看到哪条规则返回 200、哪条 404。
   本地目录里已有图的游戏会被跳过，不浪费网络请求；连续 12 个失败会自动停止，避免源站失效时干等。

图片命名沿用 OfflineList 规范，所以两边可以共用同一批图片文件。

### 匹配策略
- **CRC 优先**（权威），失败时可用**文件名模糊匹配**兜底（自动剔除 `(Japan)` `[CHS]` 这类标签）
- 大文件 CRC 带缓存（`data/crc-cache.json`，按 路径+大小+修改时间），第二次扫描接近瞬时
- 扫描进度实时显示，可随时停止

### 其他
- 只监听本机 `127.0.0.1`，零依赖（无需 npm install），数据全部存在本地 `data/` 目录
- 整理前强制预览计划，默认**复制**模式（绝不动源文件），移动模式需显式开启
- 深色模式：左下角「切换深色」

## 同名 DAT 会按版本取舍

同一个名字的 DAT（如同一个汉化组的 GG 清单）重复导入时，比较 DAT 里的版本号：

- **新版本更高** → 覆盖数据文件，同时**保留该清单已有的 ROM 目录、命名模板等设置**，不用重新配
- **版本相同或更低** → 直接跳过，提示已有更高版本

侧栏清单项上悬停会出现 ✕，可以直接删除该清单（只删工具内的 DAT 记录与文件，不会动 ROM 和截图）。

## BIOS 文件

与纹理包同机制：勾选「BIOS 文件与主文件放进同一个文件夹」后，带「(Bios)」的条目会和主文件进同一个子文件夹，文件夹名用不带标记的那个。仅「保留原始文件」模式生效。

## 同一个文件被多条记录引用

如果一个文件同时命中 DAT 里的多条记录（CRC 相同、多条记录），程序会：

- 只让**第一个条目**负责输出，其余条目标记为跳过（不会重复复制，也不会因为找不到源文件而报错）
- 这个文件**不会**被判定成「重复副本」移走或删除

整理预览里会显示「共享文件保留 N 个」。

另外，**CRC 相同的多个文件不算「多份副本」**：扫描统计和整理判定都按 CRC 去重，内容一样的文件（例如不同叫法的 BIOS）不会被误报成重复，也不会被改成同一个名字互相覆盖。侧栏进度条在不到 100% 时显示黄色，100% 为绿色。

## 自动归类

侧栏底部有一个「待分类文件夹」。把没整理过的文件丢进去，点「自动归类」：

1. 逐个清单扫描该文件夹，与各自的 DAT 比对（CRC 优先）
2. 命中的文件按**该清单自己的设置**送到输出目录、按模板改名，多盘 / 纹理包 / BIOS 分组同样生效
3. 未命中的文件原地不动，交给你自己处理
4. 归位后自动刷新各清单的拥有数

用的是「移动」还是「复制」跟随每个清单的设置。

## 一键批量

顶部「批量 ▾」菜单可以一次处理所有清单：

| 操作 | 范围 |
|---|---|
| 更新所有 DAT | 有订阅地址的清单 |
| 扫描所有清单 | 配了 ROM 目录的清单 |
| 整理所有清单 | 已扫描且配了输出目录的清单 |

串行执行、逐个显示进度；整理前先确认，结束后汇总成功 / 失败 / 跳过数量。

## 默认识别规则

新建清单时以下三项**默认开启**，操作方式**默认为移动**：多盘分组、纹理包分组、清理空文件夹。

> 已有清单保留各自原来的设置，可在设置面板里调整。

## 语言标签

`CHS` → 简体中文（绿）、`CHT` → 繁体中文（蓝）、`CHS&CHT` → 两个都显示、`AI` → AI 汉化（灰）。

## 分发打包

两种开箱即用的产物，均在 `dist/` 下生成：

### Windows 便携版（分享给朋友）

```bash
node tools/build-windows.js
```

产物 `dist/ROMKit-Windows-便携版.zip`（约 32 MB）：解压后双击 `ROMKit.exe` 即用，
无需安装 Node.js；web 资源已内嵌，数据保存在 exe 旁边的 `data\` 目录。
脚本内置功能自检（隔离端口实跑 API / 页面 / 配置写入），全部通过才会产出 zip。

### 飞牛 fnOS 原生应用（.fpk）

```bash
node tools/fetch-fnos-deps.js   # 首次：下载 fnpack + 双架构 node（约 64 MB）
node tools/build-fnos.js        # 打包 → dist/ROMKit-fnos-<version>.fpk
node tools/build-fnos.js --no-bump  # 不想升版本时用这个
```

每次打包会**自动递增修订号**（如 2.14.0 → 2.14.1）：fnOS 上版本号相同的包无法覆盖安装，
递增后可以直接增量覆盖升级。`server.js` 里的 `VERSION` 是唯一版本源，构建脚本会同步写进
`fnos/manifest`（Windows 包也读同一个值，所以两个产物版本始终一致）。

产物为 `platform=all` 的单包（内置 x64 / arm64 两个 node 二进制，安装时按 CPU 架构
自动选择），在 fnOS 应用中心「手动安装」即可。要点：

- 端口 8765（`manifest` 的 `service_port` 与桌面入口 `app/ui/config` 保持一致，构建时会校验）
- 数据目录为 `TRIM_PKGVAR`（卸载时才清理）
- **目录选择器是服务端浏览**：Windows 罗列盘符，fnOS 罗列「已授权目录 → 共享目录 →
  存储空间 `/vol1`… → 文件系统根目录」，因此选的是 NAS 上的真实路径（浏览器本地文件
  选择器在 NAS 场景下没有意义，且 http 非安全上下文下不可用）
### 存储位置

三处可配（飞牛在**安装向导**里填，桌面版在清单设置 →「存储位置」里改）：

| 位置 | 环境变量 | 说明 |
|------|----------|------|
| DAT 保存位置 | `ROMKIT_DAT_DIR` | 导入与在线更新的 DAT 存放目录，留空 = 数据目录下 `dats/` |
| 图片保存位置 | `ROMKIT_COVER_DIR` | 封面/截图存放目录，每个清单在其下建子目录；清单里单独指定时以清单为准 |
| 数据保存位置 | `ROMKIT_DATA` | 清单、设置、缓存（飞牛默认 `TRIM_PKGVAR`），改动需重装或改环境变量后重启 |

优先级：**环境变量（安装向导写入）> 配置文件 > 数据目录下的默认子目录**。
飞牛上填了自定义目录后，还要到「应用中心 → ROMKit → 授权目录」里把它加一次，否则没有读写权限。

### 任务进度

每个 DAT 的扫描/整理/更新/下载图片都**独立显示进度**：底部任务条一行一个 DAT，
侧栏对应清单上也有进度条；切换清单不会互相盖掉。顶栏状态只跟随当前选中的清单。

### 目录权限

目录选择器**每次打开都重新实测**各目录的可读写性（不再依赖启动时拿到的授权目录环境变量），
进不去的目录显示 🔒「无权限」，另有「重新检测权限」按钮即时刷新。
扫描读不动的文件会在完成后列出明细与权限证据（见「查看具体文件」），可一键尝试修复权限。

- **授权目录**：fnOS 应用只能读写用户在「应用中心 → ROMKit → 授权目录」中添加的路径。
  未添加时目录选择器顶部会给出引导；选到未授权目录时会预警；打开未授权目录会提示去授权。
  授权变更会触发 `cmd/config_callback` 重启服务使其生效读写
- 图标由 `tools/gen-fnos-icons.js` 纯代码绘制（渐变圆角底 + 游戏手柄剪影），
  改设计请改生成器后重跑，不要手改 PNG


## 预留的扩展接口（后续版本）

`data/config.json` 中每个库都有 `assets` 字段，截图/封面已接入实际功能，其余为预留位：

```json
"assets": {
  "cover":      { "enabled": true, "dir": "", "storeDir": "", "pattern": "{im1CRC}" },
  "screenshot": { "enabled": false, "dir": "", "pattern": "{im2CRC}" },
  "video":      { "enabled": false, "dir": "", "pattern": "{title}" },
  "info":       { "enabled": false, "source": "" }
}
```

DAT 里已带有 `im1CRC`/`im2CRC`（封面/截图 CRC）与 `imURL`（图片服务器地址），后续接入截图集、视频、简介时可直接复用同一套目录约定。

## 已知边界

- `.7z` / `.rar` 压缩包暂无法直接读取内部 CRC，仅能按文件名匹配（可后续接入 7-Zip）
- 单个 ROM 超过 4GB 时输出 zip 自动使用 ZIP64（绝大多数模拟器前端可读；OfflineList 0.7.3 太老，超大文件建议用"保留原始文件"形态）
- PS2 的 `.chd` 本身是压缩格式，输出 zip 时自动用 store 模式（不二次压缩，速度快）
